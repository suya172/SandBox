# 2026-10-29 Architecture & Simulation Decisions

## 1. グリッド解像度: `256 × 144` の採用
- **背景**: `SPEC.md` 内に `240×135`、`256×144`、`320×180` の候補が存在した。
- **決定**: `256 × 144` (16:9, 36,864 セル) を採用。
- **理由**:
  - `16 × 16` のチャンク分割を行った際、`256 / 16 = 16`、`144 / 16 = 9` となり境界端数チャンクが一切発生せず、ビットシフト演算 (`x >> 4`, `y >> 4`) で高速にチャンクインデックスを参照できる。
  - RLE 圧縮後の URL 共有文字列長もコンパクトに収まり、Canvas 2D の 60FPS 維持にも十分な余裕がある。

## 2. 二層 SoA (`TypedArray`) グリッドによるプロシージャル建築表現
- **背景**: 太鼓橋の支柱裏を水や蒸気が通過する挙動、および水車・風車の羽根に流体が当たって通過しつつ回転力を与える挙動をクリーンに表現する必要がある。
- **決定**: 前景物理配列 (`type`, `temp`, `meta`, `charge`, `flags`) に加え、背景構造配列 (`bgType`, `bgMeta` — 計 73.7 KB) を設ける二層 SoA 構成を採用。
- **理由**: オブジェクト確保（GC負荷）をゼロに保ちつつ、前景の流体移動ロジックを複雑化させずに背景構造物との相互作用（羽根車の回転トルク検出・スプライトの橋上歩行・環境苔装飾）を実現できるため。

## 3. PNG `tEXt` チャンクを用いたロスレス・ワールド埋め込み
- **背景**: サーバーレスで1枚のPNGスナップショットからワールドを共有・インポートできる仕様が求められている。
- **決定**: Canvas から生成した PNG バイナリの `IEND` チャンク直前に、CRC32 付きの標準 `tEXt` チャンク（キーワード `TerraWeave`、値は RLE+Base64 文字列）を注入し、ドラッグ＆ドロップ時に同チャンクをパースして復元する。
- **理由**: ピクセルRGB下位ビットへのステガノグラフィーと比較して画像の視覚劣化が一切なく、リサイズされない限り100%確実にバイナリ整合性を検証（CRC32）しながら高速にデコードできるため。
